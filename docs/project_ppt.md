# 자폭 무인수상정 군집 방어

### LLM 기반 임무배정 + 점수맵 강화학습 다중 에이전트 방어 체계

**LLM-Based Task Allocation and Score-Map Reinforcement Learning
for a Multi-Agent Defense System against Suicide USV Swarms**

윤영준 · 방현태(충남대) · 전유라 · 김덕환(KAIST) · 윤원근(충남대)

MobRobGPT · 2026

---

## 문제 — 비대칭 위협

<!-- FIG: fig1_concept -->

```
          적 USV 10척 (9.0 m/s)  ─── 여러 방위에서 동시 돌진
        ↘        ↓        ↙
             ╭───────╮
             │  모선  │   고가치 함정 1척
             ╰───────╯
        ↗        ↑        ↖
        아군 방어정 3척 (6.0 m/s)  ─── 적보다 느리다
```

- **수적 열세**: 방어 3 : 위협 10 → 최적 할당으로도 **남는 표적**이 생긴다
  <span class="small">(무기-표적 할당, Ahuja et al., 2007)</span>
- **속도 열세**: 아군 6.0 m/s < 적 9.0 m/s → **추격으로는 못 따라잡는다**
- **비용 열세**: 수천 달러 표적에 수십만~수백만 달러 요격탄

> 세 열세가 동시에 성립한다 — 기존 대응 문법이 통하지 않는다

---

## 기존 대응의 한계

| 대응 | 방식 | 한계 |
|---|---|---|
| **연성(soft-kill)** | 통신·항법·센서 교란 | 위협 자체는 **온전히 남음**<br>전파를 안 쓰는 **유선 조종 표적엔 무효** |
| **경성(hard-kill)** | 직접 타격 | **역전된 비용 구조**(요격탄 ≫ 표적)<br>한 번에 한 표적 → **포화** |

<span class="small">Wang et al., 2021 / Sutea, 2026 / Rumbaugh, 2024</span>

---

## 제안 — 저비용 그물에 의한 물리적 포획

```
   적 진행 방향
        ↓                     그물벽을 적의 접근 회랑에
   ━━━━━━━━━━━━  ← 그물벽      "미리" 가로질러 놓는다
        ↓
    추진기에 얽힘 → 무력화
```

- **통신 방식과 무관**하게 작용 → 유선 조종 표적에도 유효
- 표적을 **정지**시킨다 → 연성 대응처럼 위협이 남지 않음
- 그물 단가 ≪ 유도탄 → **비용 구조가 뒤집히지 않는다**
- 아군이 느린 문제를 **추격이 아니라 선점 차단**으로 우회

### 성능 지표 — 포획률

$$\mathrm{Capture\ Rate}=\frac{N_\mathrm{cap}}{N_\mathrm{cap}+N_\mathrm{brc}}$$

<span class="small">$N_\mathrm{cap}$ 포획된 적선 수 · $N_\mathrm{brc}$ 돌파한 적선 수</span>

## 핵심 구조 — 판단 주기가 다른 2계층

<!-- FIG: fig2_architecture -->

```
 ┌─ 전략 계층 ─────────────────────────────┐   느린 주기 (25 step 기본, --replan)
 │  전장상태(기하량 선계산) ─▶ [ LLM ] ─▶ 배정·HOLD  │   비동기 호출
 └───────────────────────────┬─────────────┘
                             │  assign (배별 담당 무리 + 요격점)
 ┌─ 기동 계층 ────────────────▼─────────────┐   매 결정 스텝
 │  전장 래스터 ─▶ [ U-Net 점수맵 ] ─▶ 픽셀 2점 ─▶ 그물벽 │
 └─────────────────────────────────────────┘
```

- **역할 분리**: 유연한 판단(LLM) / 실시간 협조 기동(학습된 정책)
- **비동기**: LLM 응답 지연이 제어 루프를 **막지 않는다** — 응답을 기다리는 동안에도 기동은 진행
- 재계획 사이 구간을 강화학습 루프가 채운다

---

## 전략 계층 ① — 입력: 기하량을 미리 계산해 넘긴다

<!-- FIG: fig3_commander -->

LLM에게 **좌표 원시값 대신 판단에 필요한 숫자를 계산해서** 준다.

| 신호 | 의미 | LLM이 하는 판단 |
|---|---|---|
| `to_clusters` [{dist, turn}] | 각 무리 요격점까지 이동거리·선회량 | 최근접·최소선회 매칭 |
| `bearing_from_center` | 모선 기준 방위 | 같은 쪽 배 고르기 |
| `net_covered` | 이미 그물로 차단됨 | 그 무리 **건너뛰기** |
| `route_hits_net` | 경로가 설치 그물 관통 | 격침 위험 → **HOLD** |
| `assigned_cluster` | 직전 배정 | **연속성** 유지 |

> LLM은 **산술이 약하고 응답이 느리다.** 그래서 암산을 제거하고
> 역할을 **표적-아군 할당 한 가지**로 국한했다.

## 전략 계층 ② — 출력: 최소 스키마 + 근거 우선

```json
CommanderPlan {
  rationale:   "판단 근거를 먼저 서술"      ← ① 생각
  deployments: [{cluster_id, ally_ids}]     ← ② 배정
  hold_ships:  [ally_id, ...]               ← ③ 대기
}
```

- **구조적 출력 강제** → 스키마 위반 불가, 항상 파싱 가능 <span class="small">(OpenAI, 2026)</span>
- **rationale을 맨 앞에** → 결정 후 사후정당화가 아니라 "생각한 뒤 결정"
- **최소 스키마** → 소형 모델 폭주·모순 제거

### ★ 조합 최적화 후처리를 두지 않는다

최소비용 매칭 같은 보정을 덧붙이면 최종 배정이 결국 **비용 함수의 산물**이 되어
지휘관의 전술적 의도가 가려진다 → **LLM의 결정을 하위 계층이 그대로 소비**한다.

## 배정은 기동 계층의 선행 조건

```
 LLM 배정 확정
      ↓
 배별 요격점 고정
      ↓
 요격점 중심 후보 영역(유효 마스크) 결정   ← 반경 3000 m · 방위 ±60° 게이트
      ↓
 정책은 이 영역 "안에서만" 픽셀을 고를 수 있다
```

- 배정이 바뀌면 **후보 영역 자체가 바뀐다**
- 정책은 세 경로로 배정을 인식:
  `self_intercept` 채널 · 자기상태 벡터 · **유효 마스크 하드 게이팅**
- 마스크가 곧 통제 수단 — 모델이 배정 밖을 찍는 것이 **구조적으로 불가능**

## 기동 계층 ① — 관측: 목록이 아니라 다채널 격자 지도

<!-- FIG: fig4_observation -->

모선을 중앙에 둔 **50 × 50 격자 (픽셀 252 m, 반폭 6300 m) × 15채널**

| 묶음 | 채널 |
|---|---|
| 전역 9 | `enemy_presence` `enemy_vx` `enemy_vy` `enemy_threat` `ally_presence`<br>`net_installed` `origin` `annulus` `land` |
| 배별 3 | `self_marker` `self_intercept` `self_valid` |
| 좌표 3 | `coord_x` `coord_y` `coord_r` (CoordConv) |

- **적 수가 늘거나 줄어도 입력 형태가 그대로** — 목록 입력의 가변 길이 문제 제거
- **적을 넣은 순서에 결과가 좌우되지 않음** (순열 불변)
- 합성곱은 위치 정보가 흐려지므로 좌표 채널로 **절대 위치 보존** <span class="small">(Liu et al., 2018)</span>

## 기동 계층 ② — U-Net 점수맵에서 픽셀 2점 선택

<!-- FIG: fig5_policy -->

```
 15ch 50×50 ─▶ [ U-Net (입력 해상도 유지) ] ─▶ 셀 특징 d=32
                                                    │
   자기상태 ─▶ 질의 q ──── 내적 ────────────────────┘
                            ↓
                     점수맵 (50×50)
                            ↓  유효 영역 밖은 마스킹
              1번째 픽셀 ─(특징을 q에 되먹임)─▶ 2번째 픽셀
                            ↓
                 두 점을 잇는 선분 = 그물벽 경로
```

- 두 점이 **서로를 알고** 뽑힌다 (순차 선택 + 되먹임)
- 서브픽셀 보정 ±126 m → 격자 해상도보다 정밀한 좌표
- 가까운 점 = 이동 경유점, 두 점 사이 = 그물 투하 구간

---

## 왜 좌표 회귀가 아니라 "픽셀 지목"인가

| | 연속 좌표 회귀 | **점수맵 픽셀 선택** |
|---|---|---|
| 행동공간 | 무제한 실수 | **격자로 규제** |
| 배정 위반 | 사후 클리핑 필요 | **마스킹으로 원천 차단** |
| 결정 안정성 | 스텝마다 미세 진동 | **경유점이 고정** → 기동 안정 |
| 해석 | 숫자만 나옴 | 점수맵 자체가 **판단 근거 시각화** |

> 행동공간을 규제하고 경유점을 고정하는 것이 이 설계의 핵심 이득

## 학습 — 그룹 상대 정책 최적화(GRPO)의 다중 에이전트 변형

<!-- FIG: fig6_grpo -->

```
 한 결정 시점
    ├─ 후보 행동 G개 샘플링  (1개는 휴리스틱 행동으로 채움 = 출발점 확보)
    ├─ 각 후보를 시뮬레이터로 일정 구간 진행 → 팀 보상
    └─ 후보끼리 상대 비교로 이득 산정   ⇒ 가치망 불필요
```

**개별 기여 분리(counterfactual credit)** <span class="small">Shao et al., 2024 변형</span>
팀 보상을 그냥 나누면 누가 잘했는지 가려진다
→ **한 척의 행동만 바꾸고 나머지는 고정**해 평가, 그 차이를 그 배의 몫으로

**보상 설계**
- 지배 항: **포획(+) · 돌파(−) · 아군의 그물 접촉(−)**
- 위협 근접도에 대한 퍼텐셜 항 → **최적 정책을 보존하는 형태** <span class="small">(Ng et al., 1999)</span>

관측이 **무차원**으로 정규화되어 있어 학습 가능한 부분에 절대 길이가 들어가지 않는다.

```
   12.6 km 실해역          12.6 m 수조
        └────── 같은 가중치 ──────┘
     맞출 것은 좌표와 시계뿐
```

> 축소 모형 실험 → 실해역 이식이 **재학습 없이** 가능한 설계

## 시뮬 → 실센서 이식

| 층 | 시뮬 | ROS2 실센서 |
|---|---|---|
| 진입 | `CommandedCnnEnv` | `ROS2CnnEnv` (상속, `step()` 만 교체) |
| 관측 | 시뮬 상태 → 래스터 | GPS/AIS/레이더 → 같은 래스터 |
| 정책 | **동일 체크포인트** | **동일 체크포인트** |
| 출력 | 시뮬 WP | 위경도 WP 발행 |

**실센서에서 직접 관리해야 하는 상태 3개** (시뮬이 대신 세어주던 것)

- `a_nets` — 배별 남은 그물 수
- `doing_net` — 현재 그물 전개 중인가 (전개 중 재배정 금지 = lock-in)
- `net_installed[200,200]` — 이미 깔린 그물 누적 격자

> 위험한 건 모델이 아니라 **유효 마스크와 배정**이다.
> 이 둘이 틀리면 모델은 **에러 없이 조용히** 엉뚱한 곳을 찍는다.

## 안전장치

- **검증/정제(sanitize)** — 중복 ally·무효 id 등을 거부가 아니라 **수리** → 항상 유효 계획
- **폴백** — LLM 실패/타임아웃/스키마 위반 시 **위협비례 휴리스틱**으로 계속 방어
- **모선 전용 회피(`mother_keepout`)** — APF 를 꺼도 **항상 ON** (모선 충돌·격침 방지)
- **적 육지 우회(`enemy_land_avoid`)** — 항상 ON
- **그물 lock-in** — 전개 중인 그물은 완료까지 중단·재배정 금지

> 어떤 상황에서도 **방어가 끊기지 않도록** 다중 안전망

## 한계와 향후

**현재 한계**
- 정량 평가 미완 — 위 표가 비어 있다
- 그물벽 길이 정의 불일치(150 m vs 450 m) 미확정
- 배정 통제성: 자연어 의도("왼쪽 먼저")의 추종이 아직 일관되지 않음

**향후**
1. **코드가 추천 배정을 힌트로 제공** → LLM은 수용/조정만
   (효율은 코드가 보장, 의도는 LLM이 반영)
2. 상태 신호 강화 — 무리별 `time-to-breach`, 교차 발생 플래그
3. 파인튜닝은 A·B 개선으로도 의도 추종이 안 될 때만
   <span class="small">(코드로 계산 가능한 "좋은 plan"이면 파인튜닝은 불필요)</span>
4. 축소 모형 수조 실험 → 실해역 검증

## 요약

- **문제**: 수적·속도·비용 3중 열세의 자폭 USV 군집 → 기존 soft/hard-kill 문법이 통하지 않음
- **접근**: 저비용 **그물 물리 포획** + 추격이 아닌 **접근 회랑 선점 차단**
- **구조**: 판단 주기가 다른 **2계층 비동기** — LLM 전략 / 학습 정책 기동
- **지휘관**: 기하량 선계산 · 구조적 출력 · 근거 우선 · **조합 최적화 후처리 없음**
- **기동**: 15채널 격자 관측 → **U-Net 점수맵에서 픽셀 2점** → 그물벽
- **학습**: GRPO + **한 척만 바꿔 평가**하는 기여 분리, 가치망 없음
- **이식성**: 관측이 무차원 → **스케일 불변**, 동일 체크포인트로 시뮬·실센서
