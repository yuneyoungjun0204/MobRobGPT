## 1. 한 줄 요약

> GRPO 는 후보당 **스칼라 하나**만 쓴다. 그래서 이벤트(포획·돌파)만으로는 창(window)마다
> 변별이 안 된다. **이벤트 + 포텐셜 shaping + 밀집 기하 신호**를 더해
> 180 step 창에서도 후보 간 순위가 갈리게 만든 것이 이 설계의 전부다.

보상은 **팀 단위 스칼라**다 (배별 분해 없음). 창 길이는 학습 시 `eval_period = 180 step`.

## 2. 전체 식

```
R  =  R_event                                  ← Unity 패리티 이벤트
   +  γ·Φ(s′) − Φ(s)                           ← 위협 포텐셜 shaping (최적정책 불변)
   +  w_raycov·raycov  +  w_coverage·coverage  ← 방어 성공의 선행지표
   +  w_place·place    +  w_assign_path·approach  +  w_idle·idle
   +  w_eff·eff        +  net_touch
   −  w_obstacle·obstacle                      ← 충돌 회피 (APF + 윈도우 최소거리)
   −  w_smooth·smooth  −  w_consist·consist    ← 궤적 품질
   −  w_clear_net·net_clear  −  w_anchor·anchor   ← 이 실행에서는 둘 다 0 (§5)
```

### 2.1 이벤트 항 `R_event` (`reward.py::window_reward_vec`)

```
R_event = r_capture · 포획수 · (1 + w_cap_dist · 포획거리_norm)
        + r_breach  · 돌파수
        + r_ally_collision · 아군충돌  +  r_obstacle · 모선충돌  +  r_land · 육지충돌
        + time_penalty · steps
        − w_path · path_dist_norm  −  w_net · 사용그물수
        + [종료 시]  ( r_wipeout            잔존 적 = 0 )
                     ( r_survive · 잔존수    그 외      )
```
`path_dist_norm = Σ이동거리 / (창길이 × ally_speed × P)`

### 2.2 위협 포텐셜 Φ

```
Φ(s) = − w_threat · Σ_{살아있는 적 m}  clip( 1 − d(적 m, 모선) / 6300 , 0 , 1 )
```
- potential-based(`γΦ(s′) − Φ(s)`) 라 **최적 정책을 바꾸지 않는다.**
- 적이 모선에서 멀어지거나 죽으면 ↑ → 돌파(희소·이산)의 **매끄러운 대체 신호**.

## 3. 가중치 표 (이 실행에서 실제로 쓰인 값)

### 3.1 이벤트 — 희소·큰 크기

| 이름 | 값 | 의미 |
|---|---:|---|
| `r_capture` | **+13.5** | 포획 1척 |
| `r_wipeout` | +8.0 | 전멸 (종료 보너스) |
| `r_breach` | **−8.0** | 돌파 1척 |
| `r_survive` | −5.0 | 종료 시 잔존 적 1척당 |
| `r_ally_collision` | −30.0 | 아군–아군 충돌 |
| `r_obstacle` | −30.0 | 아군–모선 충돌 |
| `r_land` | −30.0 | 아군–육지 좌초 |
| `r_net_touch` | −13.0 | 완성된 그물에 아군이 닿음 |
| `w_cap_dist` | **0.0** | 조기 제압 가산 — **끔** |
| `time_penalty` | **0.0** | 시간압 — **끔** |

### 3.2 밀집 신호 — 매 창마다 값이 있는 것

| 이름 | 값 | 정의 |
|---|---:|---|
| `w_threat` | **3.0** | Φ 가중 (위 §2.2) |
| `gamma` | 0.99 | shaping 할인 |
| `w_raycov` | **1.6** | 단일커버 레이캐스트 (아래) |
| `w_coverage` | 0.1 | 적→모선 ray 가 **설치 그물**에 막힌 적 비율 ∈[0,1], `coverage_rays=16` 샘플 |
| `w_consist` | **0.3** | ‖route[t] − route[t−1]‖ 평균 / `wp_max_len(450)` — 경로 튐 억제 |
| `w_smooth` | 0.3 | 누적 선회량 / (창길이 × `ally_max_turn`) ∈[0,1] |
| `w_path` | 0.5 | 이동거리 페널티 (정규화) |
| `w_net` | 0.3 | 그물 1개당 비용 (포획 +13.5 보다 훨씬 작음 → 잡으면 이득) |
| `w_eff` | 0.1 | 경로 효율 = 직선변위 / 이동거리 ∈[0,1] (1 = 직진) |
| `w_place` | 0.1 | 그물 배치 정렬 (아래) · `place_scale = 300 m` |
| `w_assign_path` | 0.1 | 배정 요격점까지 **거리 감소량** / (창길이 × speed), clip[−1,1] |
| `w_idle` | 0.2 | 미배정·생존 배가 **안 움직일수록** ↑ (예비는 쉬어라) |
| `w_wp_good` / `w_wp_bad` | 0.2 / 0.2 | WP 품질 보너스 / 페널티 |

**`raycov` — 단일커버 레이캐스트** (이 설계의 핵심 niche)
적→모선 ray 를 아군 **계획 그물벽**이 막으면 커버.
```
값 = raycov_net_bonus(1.3) × ( 1 + raycov_far_gain(1.0) × (1 − t_block) )     … 커버 시
     0                                                                        … 두 벽이
         raycov_collide_m(400 m) 이내로 같은 ray 를 막으면 (= 중복 = 충돌 예정) 무효
살아있는 적 1척당 평균으로 정규화
```
- `t_block` = 차단 지점의 진행도 (0 = 적 쪽, 1 = 모선 쪽) → **멀리서 막을수록 가산** (종심 방어)
- **중복 배정을 보상 수준에서 직접 억제**한다 — 두 배가 같은 적을 막으면 둘 다 0점
- `raycov_plan_path = True` → 접근 세그먼트(현위치→첫 WP)도 인정

**`place` — 그물 배치 정렬**
그물 중점이 적→모선 진입 코리도 위에 있고, 경로선에 가까울수록 ↑.
```
score = gate(t) · exp( −perp / place_scale(300 m) )
gate(t) = clip((t−0.05)/0.15,0,1) · clip((1−t)/0.15,0,1)     t = 코리도 진행도
```
**자기 배정 클러스터의 적만** 카운트 (분업 강제). 전개한 배만.

### 3.3 충돌 회피 `obstacle` — `w_obstacle = 0.25`

```
obstacle = ally_rep  +  mother_avoid_w(2.0)·mother_rep
         +  w_mother_dmin(3.0)·Σ prox_m²   +  w_ally_dmin(3.0)·Σ prox_a²
```

| 요소 | 식 | 파라미터 |
|---|---|---|
| 아군–아군 척력 | `½·η·(R/max(d, d_min) − 1)²`, `d < R` 일 때만 | `avoid_r R = 600 m`, `avoid_eta η = 0.6`, `avoid_dmin = 90 m` |
| 아군–모선 척력 | 같은 식, 거리 = `d(모선) − ally_mother_radius(300)` | `mother_avoid_r = 500 m`, 가중 `mother_avoid_w = 2.0` |
| **모선 근접** `prox_m` | `clip( (300+500 − dmin) / 500 , 0, 1 )²` | `w_mother_dmin = 3.0` ← 이 실행에서 켬 |
| **아군 근접** `prox_a` | `clip( (600 − dmin) / 600 , 0, 1 )²` | `w_ally_dmin = 3.0` ← 이 실행에서 켬 |

> **`dmin` 을 따로 둔 이유** (`dmin_track=True`).
> 척력 항은 `pos_end × a_alive` 로 계산한다. 그런데 충돌한 배는 `_micro` 에서 `a_alive`
> 가 꺼지므로 **정작 벌해야 할 케이스에서 기여가 정확히 0** 이 되고 사후 `r_obstacle(−30)`
> 만 남는다. `dmin` 은 **창 안의 최소거리(죽기 전 최근접)** 라 그 사각을 메운다.
> 제곱이라 붙을수록 급가중.

### 읽는 법 (슬라이드에 넣을 세 문장)

1. **포획이 지배한다** — 창의 46.8 % 에서만 발생하지만 크기가 커서 |기여| 의 57.8 %.
   나머지 절반의 창에서는 **Φ 가 유일한 큰 신호**(비영 100 %, |기여| 16.1 %)다.
   이벤트만 썼다면 절반의 창이 무차별해져 GRPO 순위가 안 갈린다 — 이게 shaping 을 넣은 이유.
2. **Φ 는 평균 +0.36 인데 |평균| 은 7.40.** 창마다 크게 흔들리지만 에피소드 전체로는
   거의 상쇄된다 — potential-based shaping 이 설계대로 **정책은 안 바꾸고 변별만 준다**는 증거.
3. **raycov 는 비영 62.5 %** 로 이벤트가 없는 창을 메우는 두 번째 밀집 신호다.
   창을 25 step 으로 줄여 재면 raycov 의 점유가 **25.1 %** 로 뛰어 capture(26.2 %) 와 맞먹는다
   — 짧은 지평에서는 이쪽이 사실상 주 그래디언트.

## 5. 켜져 있지만 실제로는 0 인 항 — 발표에서 빼거나 각주 처리할 것

| 항목 | 가중치 | 왜 0 인가 |
|---|---:|---|
| `anchor` (잔차 앵커) | `w_anchor = 1.5` | **CNN 점수맵 행동에서는 항상 0.** `_apply_cnn_actions` 가 `_resid_mag = 0` 으로 둔다 (잔차 개념이 없는 절대 좌표 행동). 부채꼴/잔차 행동 모드용 항이다. |
| `net_clear` | `w_clear_net = 0.0` | 가중치 자체가 0 |
| `w_cap_dist` | 0.0 | 조기 제압 가산 끔 |
| `time_penalty` | 0.0 | 시간압 끔 |
| `r_capture_indiv` | 0.3 | joint 모드 전용, **현재 미연결** (코드 주석 명시) |
| `idle` | `w_idle = 0.2` | 가중치는 살아있지만 비영 0.9 % — 거의 모든 배가 배정되어 발동할 일이 없다 |

## 6. 설계 논지 (슬라이드 스토리라인)

| # | 문제 | 대응 | 근거 |
|---|---|---|---|
| 1 | GRPO 는 후보당 스칼라 1개 → 창마다 변별 필요 | 이벤트 + Φ + 밀집 기하 신호 | 측정: 창의 53 % 에 포획 이벤트 없음 |
| 2 | 돌파는 희소·이산 spike | Φ = 적 근접도 합의 음수 (potential-based) | 최적정책 불변 · 실측 평균 +0.36 ≈ 0 |
| 3 | 중복 배정 = 충돌 예정 | `raycov` 단일커버 — 2대가 400 m 안에서 같은 ray 막으면 **둘 다 0점** | `raycov_collide_m = 400` |
| 4 | 얕게 막으면 반응 시간 없음 | `raycov_far_gain` — 멀리서 막을수록 ×(1+1.0·(1−t)) | 종심 방어 |
| 5 | 충돌한 배는 척력 신호가 사라진다 | 창 **최소거리** 기반 `w_*_dmin` 제곱 페널티 | `dmin_track=True`, 모선/아군 각 3.0 |
| 6 | 경로가 매 결정 튀면 추종 불가 | `w_consist` — 직전 route 와의 거리 페널티 | 비영 99.1 %, |기여| 3.3 % |
| 7 | 그물을 아무 데나 깔면 안 됨 | `place` — **자기 배정 클러스터**의 진입 코리도만 인정 | 분업을 보상으로 강제 |
